## What's new

**图片可以拖进对话了，模型真的能看到。** 编辑器里的截图、设计稿、报错窗口直接拖进来，随消息一起送给模型；不是把图存起来占位，而是作为图片内容进入这一轮对话。图片能力由 provider 显式声明，单张默认 20 MiB（上限 32 MiB）、每轮最多 8 张、每轮总量 32 MiB；超出能力或预算的那一刻，界面会写清楚**哪一张没送达、为什么**，而不是安静地少一张图。只有模型真的收下并返回后才记送达回执。

**工作空间可以只授权一个文件。** 以前想把一个配置文件交给智能体，只能授权它的整个上层目录；现在拖一个文件进去就是精确授权这一条路径，父目录其余内容仍然读不到、也改不了。`project.toml` 里对应 `[[workspace.files]]`，单文件快照只捕获该文件本身，恢复时不会把父目录的其他改动一起带回来。

**对话里的文档引用能点开读，也能就地改。** `README.md:42` 这样的引用现在可点：只读查看器带一个按文件夹分组、像书架一样的空态，点一本就在右栏打开；编辑入口是另一张卡，有文件夹树、monaco 和 `write_file` 逐次审批。两张卡职责分开——阅读态不会为了编辑去加宽重排，编辑态也不会因为想看一段就长出文件树。`localhost:8080`、`10:30`、`v1.2:3` 这类不该被当成路径的东西有专门规则挡掉，宁可漏判也不给假链接。

**屏幕边缘多了一个伙伴胶囊。** 在左或右边缘停靠一颗胶囊，点击或向内滑动展开成面板，面板始终置顶、切到其他应用自动收起，可以拖动位置、换边停靠，位置会记住（`desktop.toml [companion] enabled`，默认关）。这一版只交付胶囊与面板的停靠、拖动、展开——面板里承载什么还在做，别指望它现在能干活。

**智能体有了自己的形象。** 内置 deepseek 与 geptia 两只，新装的智能体实例随机分一只，智能体中心可以逐个改；对话流、子智能体卡片、空间模式的归属标签、侧栏都显示同一只，多个窗口之间同步。之前那套「宠物」在设置里改名为「伙伴形象」。

**登录只做一次。** 上一版接上了 Logto，但每次启动桌面端都会拉一个新 Core，会话只在内存里，于是每次开应用都要重登。现在登录状态加密落盘（Windows DPAPI / POSIX AES-GCM，无密钥环时不写明文），启动时同步读盘、后台用 `/auth/me` 复核——只有 401 才清空，网关还没起来时保留缓存。会话窗口从 12 小时改成 30 天并滑动续期，token 过期用 refresh token 静默换新。

## What's changed

### 新能力

- **图片多模态链路**：HTTP provider 用 `image_input` opt-in（含按模型覆盖），ACP 从最近一次 initialize 的能力快照自动判断，OpenCode/TUI/Headless 恒关；图片以原生内容块进入模型，参数编辑器新增图片轴，只读通道不给假开关。
- **工作空间卡片**：右侧功能面板新增第 14 张卡，是源文件夹的第二个入口而非第二套授权——增删目录、设主文件夹四个动作全部落到既有的 `PUT /storage/scopes/{id}/workspace`，同一摘要条件、同一次原子替换，没有新端点。
- **附件是一等事实**：`message_attachments` 记录来源、项目、原路径、是否送达、属于哪个 run、什么时候送达；工作空间卡按项目展示全部来源的缩略图与送达状态。
- **附件暂存**：没有会话时附件以 `staged` 保留本地字节、不建会话也不上传，发送时才创建会话并上传。
- **权限策略可编辑**：`runtime.toml [approval]` 新增 `risk_max`、`max_per_run`、`human_only_tools`、`delegation_blocked_tools`；删除类工具按后缀直接拒绝，`full-access` 冻结模式是唯一例外。
- **文档书架**：扫描工作区时深度 3、最多 48 个目录 / 240 篇、并发 5，被截断时明说「只列出前 N 篇」，且只收散文类扩展名——书架不该变成排序更差的文件浏览器。

### 修复

- **打开存储页会卡死整个应用**：`busy` 同时表示「在读」和「在写」，而三处导航拦截都读它，于是统计还在跑的时候既切不走也关不掉窗口。现在读是 `loading`（不拦导航），只有未落盘的写才是 `busy`。
- **存储统计把下限当精确值显示**：遍历改成分类型 400 ms 预算，超预算返回 `truncated: true` 并从 schema 一路贯通到界面，显示为「N+」而不是一个看起来很确定的数字。
- **发送按钮整轮转圈**：`busy` 不再并入 `working`，发送闩只等到 Core 收下消息就释放，run 的进展交给对话流表达；停止按钮改看 `canStop`，发送结束不消失。
- **不同 run 的事件互相覆盖**：事件流按 `seq` 去重，而序号是 per-run 的——两个 run 的同序号事件会顶掉对方。键改成 `(run, seq)`。
- **没有会话时仍维持一条空转的事件流**：Core 对不带会话的订阅会重放整个作用域的历史，欢迎页却根本不消费它。现在不建立连接，宿主恢复可达时再补一次。
- **文件搜索被单行压缩文件撑爆**：超长行改为围绕首个命中的 400 字符窗口（带 `content_truncated` / `content_start` / `line_length`），每行最多 16 个 submatch，需要全文就 `read_file`。
- **`client secret` 曾明文提交进仓库**：现在只保留 Authority / ClientId / RedirectUri，密钥走环境变量 `TinadecOidc__ClientSecret`。
- 智能体形象的偏好键统一并跨窗口同步；子智能体头像被裁成左上角一帧的问题已修；对话流头像改为左侧整块。

### 性能

- **会话事件重放**：`MaterializeAsync` 改为每本 run 日志只开一次文件句柄。实测 1,295 条事件的会话从 692–1,334 ms 降到 40 ms（约 17×），所有重放调用点同时受益。
- **重放按事件类型在索引里过滤**：orchestration 只取它需要的几种事件，工具时间线只取 `tool.*`，大部分行根本不需要读文件。
- **事件跟随不再全量扫索引**：原来每 200 ms 把会话（无会话时是**整个作用域**）的索引行读回内存再过滤，5,197 行约 33 ms/次、每秒 5 次。现在按每个 run 的 `last_event_sequence` 水位做增量范围读。
- **设置页冷启动**：停在某个分区时不再为没打开的分区发请求（此前一挂载就发 16 个，全部属于「模型」与「智能体中心」）；模型中心七个读合并成一次 `GET /model-center/snapshot`，单分区失败只降级它自己；读缓存按「配置目录 5 分钟 / 运行时回执 3 秒」分档。
- **可观测**：Gateway 每个响应带 `Server-Timing`（错误与 404 也有），已列入 CORS 暴露头，否则真实应用里读不到；日志按 `TINADEC_GATEWAY_PERF_SAMPLE` 采样，默认 0 不写。
- **流式回答不再整篇重解析**：流式期间解析节流到最多每 80 ms 一次（12K 字符回答单次解析 20–37 ms，原来是每帧一次），落定后立即完整渲染一次。

### 升级须知

- **图片要 provider 显式开启**：HTTP provider 需在配置里写 `image_input.enabled = true` 才发送图片，ACP 只要 initialize 报了该能力就自动开。没开的通道仍然只发文字，并会说明图片未送达的原因——不是你拖错了，是这条通道没声明能力。
- **工作空间拖文件的语义变了**：拖进去默认**就地绑定原文件**，不再默认复制。要真把文件收进工作空间请点「复制进工作空间」；「附到当前对话」只预填附件，不创建会话。v0.4.0 及以前复制进来的文件不受影响。
- **已下载的形象需要重新下载一次**：`宠物` 改名为 `伙伴形象`，存储目录同时从 `userData/pets/` 换成 `userData/companion-avatar/`，旧目录**没有做迁移**。内置的 deepseek 与 geptia 会自动播种到新目录，你之前从 Petdex 下载的其他形象在列表里会消失（文件仍在旧目录，没删）。这是这一版已知的疏漏。
- **伙伴胶囊默认关闭**：设置 → 常规 → 伙伴模式打开后立即出现，无需重启。
- 登录会话寿命 12 小时 → 30 天并滑动续期，前提是这次登录拿到了 refresh token；没有 refresh token 的旧会话到期仍需重新登录。
- 自建或开发环境需要设 `TinadecOidc__ClientSecret` 环境变量（双下划线映射配置节），否则客户端认证不可用。
- 权限策略若已有自定义 `runtime.toml`，新字段缺省时按默认值走（`risk_max = low`、`max_per_run = 32`），不需要手写补齐。
