模块由两个项目组成：`TinadecTools`（.NET 10 可执行程序）和 `TinadecTools.Generators`（Roslyn IIncrementalGenerator）。

- 入口 `Program.cs` 通过 stdin/stdout 的 JSON 行协议循环接收 `ToolCallRequest`，经 `ToolRegistry.DispatchAsync` 分发给已注册的处理器，异常统一转为 `ToolCallErrorResponse` 输出。
- 抽象层位于 `Abstractions/`：`ToolCalling.cs` 定义请求/响应/错误模型与 `JsonSourceGenerationContext`；`ToolFunctionAttribute` 标记工具方法；`ToolHandlerBase<TArgs,TResult>` 提供非静态工具的基类；`ToolRegistry` 维护 toolId→handler 字典并提供泛型注册重载。
- 生成器 `ToolFunctionGenerator` 扫描带 `[ToolFunction]` 的方法，自动生成 `GeneratedToolRegistry.RegisterAll()`，将方法签名映射为 `ToolRegistry.Register<TArgs,TResult>` 调用，实现零手写注册。
- 工具按功能分组在 `Tools/` 下：`FileRW/`（工作区路径解析、文件读写锁）、`Git/`（封装 git CLI，复用 `TerminalRunner`）、`Mcp/`（Model Context Protocol 客户端池与服务仓库）、`Command/`（沙箱命令工具）。
- 运行时代码在 `Runtime/`：`TerminalRunner` 统一子进程执行（超时、输出截断、安全终止）；`Sandbox/` 通过 `ISandboxBackend` 抽象平台差异，Windows 下由 `WindowsSandboxBackend` 使用 JobObject、ACL、DPAPI 等 Win32 API 实现隔离，非 Windows 回退到 `UnsupportedSandboxBackend`。
- 依赖方向单向：Tools → Runtime → Abstractions；生成器仅依赖 Microsoft.CodeAnalysis，不反向依赖主程序。
