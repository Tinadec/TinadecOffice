项目采用分层 + 插件式模块架构，由 `TinadecCore.slnx` 将解决方案划分为四层：
- `/src/foundation/`：基础层（Contracts、Abstractions、Persistence、VectorStore、Tenancy、Strategies），定义跨模块契约、端口接口与数据库抽象。
- `/src/modules/`：业务模块层（DmaEA、Models、Context、Prompts、Memory、Skills、LoopGuard、Lifecycle），每个模块通过实现 `IModuleRegistrar` 并暴露 `ModuleId` 和 `Register(ITinadecCoreBuilder)` 方法完成自描述注册。
- `/src/host/`：宿主层（Runtime、Api），Runtime 提供 `TinadecCoreBuilder` 与 `AddTinadecCore()` / `AddTinadecCoreMinimal()` 扩展，按依赖顺序串联各模块；Api 是 Web 入口，使用 Minimal API 暴露健康、就绪、存储与控制平面端点。
- `/tests/`：三层测试（架构断言、Agent 框架冒烟、API 端到端）。

依赖方向严格单向：Modules → Abstractions → Contracts；Persistence 为所有 DbContext 提供统一的 `UseTinadecDatabase` 扩展以切换 SQLite/PostgreSQL；Strategies 为纯 F# 无副作用内核，仅依赖 Abstractions。迁移脚本按 Provider 拆分为 `Storage.Migrations.Sqlite` 与 `Storage.Migrations.PostgreSql` 两个独立项目，启动时由 `IStorageMigrationRunner` 按需执行。
