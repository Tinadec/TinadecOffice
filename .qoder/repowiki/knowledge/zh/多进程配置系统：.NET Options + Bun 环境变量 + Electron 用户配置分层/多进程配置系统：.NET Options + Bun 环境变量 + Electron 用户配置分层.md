## 1. 使用的系统与框架
- **.NET 侧**：基于 Microsoft.Extensions.Configuration + IOptions<T> 的强类型配置绑定，通过 `appsettings.json`、`ConnectionStrings` 以及启动参数注入。
- **Bun/Elysia Gateway 侧**：纯 `process.env` 读取，集中封装在 `src/config.ts` 中，提供 `loadConfig()` / `getConfig()` 单例。
- **Electron Desktop 侧**：通过 `electron/appConfig.cjs` 实现“环境变量 > 用户配置文件 > 默认值”三层覆盖。
- **工具链/IDE 侧**：`.ponytail/config.json`、`opencode.jsonc`、`.claude/settings.local.json` 等各自独立的小工具配置。

## 2. 关键文件与位置
- `.NET Core API 配置`
  - `TinadecCore/Api/appsettings.json` — 日志、AllowedHosts、ConnectionStrings、`TinadecPersistence`、`TinadecIdentity` 等核心运行时配置。
  - `TinadecCore/Persistence/TinadecPersistenceOptions.cs` — 持久化选项模型（SectionName = "TinadecPersistence"）。
  - `TinadecCore/Tenancy/TenancyOptions.cs` — 身份/租户选项模型（SectionName = "TinadecIdentity"）。
  - `TinadecCore/Persistence/ServiceCollectionExtensions.cs` — `AddTinadecPersistence` 扩展，完成 Options 绑定、验证、连接信息解析、SecretStore 选择。
  - `TinadecCore/Runtime/TinadecCoreServiceCollectionExtensions.cs` — 模块注册入口，不直接读配置但依赖上述 Options。
  - `TinadecCore/Api/Program.cs` — WebApplication 构建、JSON 序列化策略、迁移触发、readiness 探测。
- **Gateway (Bun/Elysia)**
  - `TinadecGateway/src/config.ts` — 所有环境变量加载、模式切换（local/cloud）、认证配置、CORS、超时、代理信任等。
  - `TinadecGateway/src/index.ts` — 应用启动时调用 `getConfig()`，将配置用于 CORS、鉴权中间件、健康检查、路由监听等。
- **Electron Desktop**
  - `apps/desktop/electron/appConfig.cjs` — 网关 URL 的三层配置加载（环境变量 `TINADEC_GATEWAY_URL` > 用户 JSON 文件 > 默认值），含校验与原子写入。
- **工具链配置**
  - `opencode.jsonc` — OpenCode MCP 插件与命令配置。
  - `.ponytail/config.json` + `.ponytail/validate.js` — Ponytail 规则校验器。
  - `.claude/settings.local.json` — Claude 本地设置。

## 3. 架构与设计约定
- **按进程隔离配置源**：每个子进程（Core API、Gateway、Desktop、Tools）各自维护独立的配置加载逻辑，不存在跨进程共享的配置中心。
- **.NET 强类型 Options 模式**：所有运行时配置都映射为 POCO 类并通过 `IOptions<T>` 注入，使用 `Bind(configuration.GetSection(...))` 绑定，配合 `ValidateOnStart` 做范围校验（如 `ProbeTimeoutSeconds` 必须在 1~30）。
- **Provider 可插拔**：`TinadecPersistenceOptions.Provider` 决定 SQLite 或 PostgreSQL；SQLite 路径支持相对/绝对路径，PostgreSQL 通过 `ConnectionStrings` 名称引用。
- **敏感信息分层存储**：Windows 下使用 DPAPI 保护的 `ProtectedFileSecretStore`，非 Windows 回退到 `EnvironmentSecretStore`，由 `ISecretStore` 抽象统一访问。
- **Gateway 环境变量驱动**：全部通过 `TINADEC_GATEWAY_*` 前缀的环境变量控制部署模式、端口、后端地址、认证密钥、CORS、超时、反向代理信任等，无静态配置文件。
- **Electron 用户配置优先级**：`TINADEC_GATEWAY_URL` 环境变量拥有最高优先级，否则从用户目录 JSON 文件读取，最后回退到 `http://127.0.0.1:48730`；保存时使用临时文件 + rename 保证原子性。
- **模块化 DI 注册顺序固定**：`AddTinadecCore` 内部按依赖顺序依次调用各 `*ModuleRegistrar.Register(builder)`，确保 Tenancy → VectorStore → Lifecycle → Models → Context → Prompts → Memory → Skills → LoopGuard → DmaEA 的装配顺序。

## 4. 约定与约束
- **.NET 配置段命名**：所有配置类必须声明 `public const string SectionName`，并在 `AddOptions<T>().Bind(configuration.GetSection(SectionName))` 中使用，如 `TinadecPersistenceOptions.SectionName = "TinadecPersistence"`、`TenancyOptions.SectionName = "TinadecIdentity"`。
- **连接字符串约定**：PostgreSQL 连接串必须放在 `ConnectionStrings` 节点下，键名由 `PostgreSqlOptions.ConnectionStringName` 指定（默认 `"TinadecCore"`）。
- **SQLite 路径解析**：相对路径会相对于 `ContentRootPath` 解析，绝对路径直接使用；未配置时返回空连接字符串表示禁用。
- **Gateway 环境变量规范**：
  - `TINADEC_GATEWAY_MODE`：`local`（默认）或 `cloud`。
  - `TINADEC_GATEWAY_PORT`：默认 48730。
  - `TINADEC_CORE_URL`：默认 `http://127.0.0.1:48731`。
  - `TINADEC_TOOL_RUNTIME_URL`：默认 `http://127.0.0.1:48732`。
  - `TINADEC_GATEWAY_AUTH_REQUIRED`：云端模式下默认为 true，设为 `false` 关闭认证。
  - `TINADEC_GATEWAY_JWT_SECRET`、`TINADEC_GATEWAY_API_KEY`：云端认证凭据。
  - `TINADEC_GATEWAY_CORS_ORIGINS`：逗号分隔的额外允许来源。
  - `TINADEC_GATEWAY_TIMEOUT_MS`：请求超时毫秒数，默认 120000。
- **Electron 配置约束**：`TINADEC_GATEWAY_URL` 必须是合法 HTTP/HTTPS URL，不允许包含用户名/密码、查询参数或片段；保存时禁止覆盖受环境变量管理的值。
- **配置验证时机**：.NET 端通过 `ValidateOnStart` 在应用启动时执行 Options 验证，失败则抛出异常阻止启动；Gateway 和 Electron 端在加载时即时校验并抛出错误。
- **模块状态暴露**：`/api/v1/readiness` 暴露各模块的 `RegistrationStatus`（`registered` / `not_configured` / `disabled`），未配置的模块会以 warning 状态返回。
