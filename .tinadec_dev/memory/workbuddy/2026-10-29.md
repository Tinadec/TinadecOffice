# 2026-10-29 伙伴中心重做

## 决定与理由

- 用户给出计划文档（伙伴系统：同一应用内的独立伙伴应用），要求对比现状后重做伙伴中心。对比结论：差距是**语义与数据流**，不是样式——四张卡各开定时器，一轮 `4+N` 请求，四栏可能不同帧；没有共享选中态（点伙伴没有任何联动）；状态/连接/群分类是空壳。
- 用户拍板三点：① 侧栏沿用同一组件、**左上角品牌与右下角账号+三按钮保持一致**，中间的工作列表去掉；② 允许改 Core 契约；③ 保留 UIE 四卡（不改成三卡或专门页面）。

## 落地的改动

Core：`companion_conversations.origin`（user|companion，不能用成员表推导——两条建群路径都插 user 成员）；`GET /api/v1/companion-conversations` 跨伙伴列表；`BuildConversationsAsync` 批量化（`ListAsync` 从 4×N 次查询降到常数条）；活动 payload 补 `title / companion_name / preview`。

Gateway：路由 21 路径 / 32 操作；`CompanionConversation` schema 加 required `origin` / `can_open`。

Desktop：`lib/companionStore.ts`（单轮询 + 单飞 + 选中态 + `feedFilter`）；`lib/companionView.ts`（纯投影：筛选、按天分组、相对时间、群分类、attention 计数）；`companionText.ts` 取代 `useCompanionPoll`；四张卡重写；`AppSidebar.companionDomain`；中心页不再 `homeController.start()`；`requestCompanion(id, tab)` 直达设置面板；`PRESET_REVISIONS` + `presetRevision` 做页级布局迁移（水合路径也走 `loadLayout`）。
