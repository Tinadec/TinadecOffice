# 发送框提纯计划 — 将模式选择移出发送框并重塑样式

## 1. 背景与目标

**用户诉求**：定位发送框样式，改进样式；对话时“发送时选择的模式”相关选择器不应放在发送框内。

**现状（Explore 已验证）**
- `apps/desktop/src/components/ComposerBar.vue:128-145` 的 `.composer-selects` 承载两组路由选择器：`mode_version_id` 下拉（`api.listAgentModeTopologies()` + `跟随默认`）与 `meeting_model` 输入框，二者状态与 `loadModes()` 均自闭环在发送框内，提交时与 `dispatch_mode` 一并 `emit('submit')`。
- `composer-toolbar` 仅剩 `PermissionSelector`；旧 `ModeSelector` 已注释移除（`ponytail: ModeSelector removed — mode_version controls routing`），但 `WelcomeScreen.vue` 仍保留旧 `ModeSelector + PermissionSelector` 双选择器且 `emit('send', string)` 丢失新字段。
- 链路：`ComposerBar 内部 state → ChatPanel 透传 → HomeController.handleSend({dispatch_mode,target_run_id,mode_version_id,meeting_model}) → api.createInteraction`，视觉上 `styles.css:3481+` 的 `.composer/.composer-box` 将输入区、工具栏、路由选择器叠在同一毛玻璃大卡片内，卡片过高、焦点不突出，`chat-narrow/ultra` 时拥挤。
- 约束：Desktop 只调 Gateway，不存业务状态；`dispatch_mode` 语义为 `queued|insert|parallel`，`ask` 仅为本地 `getDispatchPref()` 的二次确认分支。

**目标**：使发送框回归“写+发”单一职责；模式路由选择上移为会话级配置条；借此重做发送框视觉（圆润胶囊、轻阴影、聚焦环、紧凑高度）。

---

## 2. 设计决策

| 决策 | 选择 | 原因 | 备选与否决 |
|------|------|------|------------|
| 新位置 | `ChatPanel` 内 `MessageList` 与 `ComposerBar` 之间的独立 `SessionModeStrip.vue` 细条（32px高，透明底，`text-xs`） | 语义最贴近“下一条消息的路由覆写”，离发送框最近但不进输入卡片；Header 已拥挤，设置页则增加跳转成本 | 放 `ChatHeader`（拥挤）、完全进设置页（每条消息覆写成本高） |
| 状态归属 | 路由状态上移至 `ChatPanel`；`SessionModeStrip` 受控、`ComposerBar` 仅保留 `dispatch_mode/target_run_id` | 单一数据源，避免父子竞态；`api.createInteraction` 契约不变，仅合并点上移 | 保留在 ComposerBar 内用 props 回填（增加耦合） |
| `dispatch_mode` 归属 | 保留在 `ComposerBar`（含 `ask` 二级菜单与队列卡片的 `steer/promote → insert/parallel`） | 属发送策略而非 Agent 拓扑，与“模式”正交 | 一并外移会使发送按钮失去就地确认能力 |
| 样式方向 | 类 ChatGPT/Claude 圆润胶囊：`rounded-[20px] shadow-sm focus-within:shadow-md`，外层承载聚焦 ring，输入区无边框 | 强化层次、缩小高度、提升可扫视性 | 维持现有 `border-muted + backdrop-blur` 大卡片（过高、焦点分散） |

---

## 3. 实施蓝图

### 3.1 新增 `SessionModeStrip.vue`

**路径**：`apps/desktop/src/components/SessionModeStrip.vue`

**职责**：会话级模式路由条，接管原 `ComposerBar` 的路由逻辑。

```vue
<script setup>
const props = defineProps<{ modelValue: string|null, meetingModel: string }>()
const emit = defineEmits(['update:modelValue','update:meetingModel'])
const modes = ref<AgentModeTopologyDto[]>([])
async function loadModes(){ modes.value = await api.listAgentModeTopologies() ... }
onMounted(loadModes)
</script>
<template>
  <div class="session-mode-strip">
    <select :value="modelValue" @change="emit('update:modelValue', $event.target.value||null)">...</select>
    <UiInput :model-value="meetingModel" @update:model-value="emit('update:meetingModel',$event)" placeholder="可选" />
  </div>
</template>
```

- `sm` 尺寸 `UiSelect/UiInput`，`gap-2`，右侧“跟随默认”说明；无边框卡片、无模糊。
- 空拓扑时显示禁用态“跟随默认”，不隐藏，避免布局跳动。
- 窄屏 `chat-narrow` 时自动折叠为 `图标+省略+下拉` 单行。

### 3.2 瘦身 `ComposerBar.vue`

**删除**：
- 状态：`modes/modeVersionId/meetingModel/loadModes` 及 `onMounted` 调用
- 模板：`.composer-selects` 整段（含两个 `.composer-select`）
- 样式：`composer-selects/select/label/input` 的 scoped CSS
- `submit()` 中对 `mode_version_id/meeting_model` 的直接读取

**新增/保留**：
- `props: { modeVersionId?: string|null, meetingModel?: string|null }`（可选，建议保留以便本地校验与 Enter 预览；或完全无知由父层合并，二选一，推荐保留）
- `emit('submit', { dispatch_mode, target_run_id })` 仅发分发字段，路由由父层合并
- 保留：`textarea.composer-input`、+ 菜单、`composer-send` 圆形按钮、`ask-menu(queued/parallel)`、`queued-card` 的 `steeringId/steerTarget/confirmSteer` 引导流

### 3.3 调整 `ChatPanel.vue` 装配

```vue
<script setup>
const modeVersionId = ref<string|null>(null)
const meetingModel = ref('')
function onComposerSubmit(e:{dispatch_mode:DispatchMode,target_run_id:string|null}){
  emit('send', { ...e, mode_version_id: modeVersionId.value, meeting_model: meetingModel.value.trim()||null })
}
</script>
<template>
  <div v-if="messages.length===0"><WelcomeScreen ... /></div>
  <template v-else>
    <ChatHeader ... />
    <MessageList ... />
    <SessionModeStrip v-model="modeVersionId" v-model:meetingModel="meetingModel" />
    <ComposerBar :modeVersionId="modeVersionId" :meetingModel="meetingModel" @submit="onComposerSubmit" ... />
  </template>
</template>
```

- `HomeController.handleSend` 与 `api.createInteraction` 契约零改动，仅调用点从 ComposerBar 内部合并改为 ChatPanel 合并。
- `WelcomeScreen` 首条消息路径：短期保持独立（欢迎流语义不同），二期再统一为同一 `SessionModeStrip` 状态，避免本次改动扩散；需在计划中明确不改 `WelcomeScreen emit(string)`，仅在 `ChatPanel` 的 `welcome-send` 分支补充默认路由（`mode_version_id:null`）。

### 3.4 发送框样式重塑

**文件**：`apps/desktop/src/styles.css` + `ComposerBar.vue` scoped

- `.composer-box`：`rounded-[20px] bg-[--surface-input] border border-border/60 shadow-sm focus-within:shadow-md focus-within:border-primary/30 transition: box-shadow 0.2s, border-color 0.2s; padding: 10px`，移除 `backdrop-blur` 的厚重感。
- `.composer-input`：去外边框，`placeholder:text-muted-foreground/60`，保留 `max-h-200px autoResize`，聚焦 ring 由外层 box 承载。
- `.composer-main`：`flex items-end gap-2`，`+` 与发送按钮改为 `rounded-full h-8 w-8`，发送按钮主色实心 `hover:scale-[1.02]`。
- `.composer-toolbar`：压缩至 `h-7` 紧凑行，仅左 `PermissionSelector` 右 `Settings` 入口，移除或弱化 `border-t`，让卡片更干净。
- `.queued-card`：上移至 `composer-box` 上方 `mb-2` 独立卡片，避免撑高输入区；`queued-run-select` 保持现有样式。
- 响应式：`conversation.chat-narrow .composer` 与 `.chat-ultra` 保持 `w-full`，`SessionModeStrip` 折叠，发送框不折行。

### 3.5 涉及文件清单

- 新增：`apps/desktop/src/components/SessionModeStrip.vue`
- 修改：`apps/desktop/src/components/ComposerBar.vue`（模板/脚本/样式）、`apps/desktop/src/components/ChatPanel.vue`（状态提升与合并）、`apps/desktop/src/styles.css`（composer 相关类）
- 不改：`HomeController.ts`、`api.ts`、`TinadecGateway/src/mappers/interactionsMapper.ts`（契约保持）、`WelcomeScreen.vue`（二期再对齐）

## 4. 数据流变更

```
现有：ComposerBar(路由+内容+分发) → ChatPanel透传 → HomeController → api.createInteraction
改为：SessionModeStrip(路由) + ComposerBar(内容+分发) → ChatPanel合并 → HomeController → api.createInteraction
```

- `dispatch_mode/target_run_id` 仍由 ComposerBar 产生；`mode_version_id/meeting_model` 由 SessionModeStrip 产生；ChatPanel 为唯一合并点。
- `localStorage tinadec.enter_pref` 的 `queued/parallel/ask` 逻辑不动；`ask` 二级菜单保留在发送按钮下拉内。

## 5. 验证计划

1. **静态**：`npm --prefix apps/desktop test`（快照与组件测试）、`npm run build` 通过。
2. **手动**（`npm run dev` 后 HomePage）：

   - `Enter` 直发、`ask` 二级菜单 `queued/parallel`、队列卡片 `引导(insert)+并列(parallel)` 四路径
   - 窄屏 `chat-narrow/ultra` 折叠、聚焦环与阴影、暗色主题
   - Network 面板确认 `POST /api/v1/sessions/{id}/interactions` 的 `mode_version_id/meeting_model/dispatch_mode/target_run_id` 落库正确
3. **视觉回归**：对比截屏，确认输入卡片高度显著降低、模式条不进卡片边框。

## 6. 风险与回滚

- **WelcomeScreen 首条消息仍为 string**：有意不改，避免扩大范围；回滚时仅 `ChatPanel` 合并逻辑需还原。
- **状态提升竞态**：ChatPanel 的 `modeVersionId` 初始化为 `null`（跟随默认），与后置 `loadModes` 异步到达无冲突。
- **样式回滚**：`styles.css` 的 composer 段为局部类，可单独 revert。
