# 修复 plan_parse_failed：规划模型输出标量字符串导致任务数组解析失败

## 根因（已用现场证据确认）

今天 5 个失败 run（`1200d08d` / `d6b315e5` / `d9053a94` / `feb146e4` / `05a89fc3`）全部死在：规划模型把 `success_criteria` 写成**单个字符串**，而 `PlannedTask.SuccessCriteria` 契约是 `string[]`（`TinadecCore/DmaEA/OrchestrationModels.cs:33-34`）。System.Text.Json（Web 默认，不强制标量→数组）抛 `JsonException` → `PlanningAgent.TryParseTasks`（`PlanningAgent.cs:148-170`）所有候选失败 → 注入 `IsFallback` 回落任务 → `RefuseSilentPlanningFallbackOnDeclaredEdges`（`FullDuplexRunEngine.cs:1844-1855`）在声明边模式拒绝派发 → `plan_parse_failed` → run 失败。证据：13:11/13:12 的 `run.plan_diagnostic` 事件头部里 `success_criteria` 均为标量字符串。

放大因素：①两个 attempt 盲发相同提示词；②`PlanningInstructions` 无类型约束、无空数组指引（早上「你好」失败疑似模型以散文回问候）；③`JsonException` 详情被吞、400 字符 head 截断在关键字段前。

## 修复内容

### A. 解析容错——标量→数组强制（治本，`PlanningAgent.cs`）
`ParseOptions` 挂自定义 `JsonConverter<string[]>`（私有嵌套类）：
- 标量字符串 → 单元素数组；`null` → 空数组；
- 数组元素：非空字符串收下，null/空串/非字符串（含嵌套数组/对象，带深度跟踪）整体跳过；
- 其余形状照旧抛 `JsonException`（如 `success_criteria: 42`）。
覆盖全部四个 `string[]` 字段（success_criteria/dependencies/required_capabilities/required_tools）。今天两次实锤失败直接被消化。

### B. 提示词类型硬约束（治因，`PlanningInstructions`）
增补（**保留**既有被测试钉住的短语「唯一机制」「不需要任何 dispatch 工具」「不要用散文拒绝或解释」不动）：
- 四个数组字段必须是字符串数组，示例 `"success_criteria": ["判据"]`，绝不能写成单个字符串；priority 是整数；
- 目标不需要执行任何工作时（问候/闲聊/纯提问）直接输出 `[]`；
- JSON 字符串里的 Windows 路径必须转义（`C:\\dir` 或正斜杠 `C:/dir`）——13:11 头部里 `C:\git\Jalium` 若为未转义形态同样炸 JSON。

### C. 重试带纠正提示（治盲发，三处规划环）
引擎新增 `internal const string PlannerRetryHint`（上次输出无法解析为合法任务图 + 只输出裸 JSON 数组 + 四字段必须是字符串数组 + 无需工作时输出 []，并携带上次捕获的 `LastParseErrorDetail` 具体报错）。三处 `for (attempt < 2)` 环——`PlanAsync`（~586 行）、`TryReplanFromSupervisionAsync`（~2668 行）、lane planner（`FullDuplexRunEngine.Lanes.cs` ~1343 行）——在 attempt>0 时把 hint 追加到装配后的提示词尾部。不改 `PlanAsync` 签名。

### D. 可诊断性补口
- `TryParseTasks` 捕获**首个** `JsonException` message（无候选时记「no balanced JSON array candidate found」），新属性 `LastParseErrorDetail` 暴露，`LogWarning` 带上；
- `run.plan_diagnostic` 事件负载增加 `parse_error` 字段；
- `MaxResponseHeadLength` 400 → 2000（有界）。

### E. 测试
- `DmaeaOrchestrationTests`（AgentFramework）：以今天事故实锤形状为回归夹具——四字段标量 Theory 可解析并被强制成数组；null/空/非字符串元素跳过；不可救形状解析失败且 `LastParseErrorDetail` 非空；提示词含类型约束与空数组指引断言。
- `FullDuplexEndpointTests`（ScriptedChatClient）：`WhenPlanner(坏形状).ThenPlanner(好数组)` → run 完成；断言第二次规划调用提示词含「重试提示」与 plan_parse_failed（钉死盲发修复）；既有 `invalidGraph`×2 失败路径测试保持绿。

### F. AGENTS.md 同步（同工作项强制）
